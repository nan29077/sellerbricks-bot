# 카카오 채널 챗봇 개발 계획 (2026-11-13)

> 상태: 계획 단계 — 개발 미착수.
> ※ 이 문서는 스튜디오 검토 전에 작성됨. **스튜디오 관련 내용(공간 데이터·연결 방식·계정 연결)은 02_스튜디오연결검토.md 와 00_인수인계서.md 가 최신 기준.** (예: 공간 데이터는 셀러브릭스에 새로 만들지 않고 스튜디오 데이터를 API로 사용, 챗봇 서버는 DB 직접 접속 대신 각 플랫폼 내부 API 호출)

## 0. 결론 요약
- **방향 1 (채널 챗봇 + 자체 서버)**: 카카오가 공식으로 열어둔 유일한 "카톡에서 묻고 → 카톡으로 답받기" 경로. **채택.**
- **방향 2 (채널 없이 카톡 메시지 직접 활용)**: 공식 API로는 **보내기만 가능, 받기(읽기)는 불가.** 양방향은 비공식 매크로(메신저봇R 등)뿐 → 계정 정지·약관 위험으로 사용 안 함. "아침 주문 요약을 셀러 카톡(나와의 채팅)으로 보내기" 같은 단방향 보조 기능으로만 활용.

## 1. 방향 2 검토 — 채널 없이 카카오톡 직접
| 방법 | 받기(셀러 질문 읽기) | 보내기(답변) | 판단 |
|---|---|---|---|
| 개인/단톡 대화 조회 API | ❌ 카카오 미제공 (데브톡 공식 답변: 이용자 간 채팅 내용 조회 기능 없음) | – | 불가 |
| 카카오톡 메시지 API "나에게 보내기" | ❌ | ✅ 검수 없이 무제한 (셀러 카카오 로그인 + 동의 필요) | 보조용 |
| 메시지 API "친구에게 보내기" | ❌ | △ 검수, 친구관계 필수, 쿼터(발신자당 일 100건 등) | 부적합 |
| 메신저봇R / PC 매크로 (비공식) | △ 안드로이드 서브폰 알림 감지 | △ | ❌ 계정 정지 위험, iOS 불가, 불안정 |
| 오픈채팅 챗봇(beta, 2026-07 카톡 업데이트) | ? | ? | 외부 개발자 등록 가능 여부 미공개 → 관찰 |
| ChatGPT for Kakao '카카오툴즈' | ✅ | ✅ | 제휴 파트너만 입점 → 중장기 제휴 과제 |

참고 — 카카오 PlayMCP: 누구나 원격 MCP 서버(HTTPS, Streamable HTTP, 도메인 필수) 등록 + 심사 가능. 단, 사용처는 Claude/ChatGPT/OpenClaw 이고 카톡 내부(카카오툴즈)는 제휴·공모전 경로만 있었음(2026-09 기준 28개 서비스).

## 2. 전체 구조
```
셀러 카카오톡
  └─ [셀러용] 카카오 채널 (구매자용 채널과 분리 권장)
       └─ 카카오 i 오픈빌더 봇 (폴백 블록 → 스킬)
            └─ ① 스킬 서버 POST /kakao/skill (5초 안에 "확인 중…" + useCallback:true 즉시 응답)
                 └─ ② 작업 큐 → AI 에이전트 (LLM + 도구 호출)
                      └─ ③ 도구 계층 (셀러 범위 강제)
                           ├─ 셀러브릭스 내부 봇 API: 주문·매출·정산
                           ├─ 스튜디오 내부 봇 API: 시설 검색·예약 가능 시간·내 예약·스튜디오 주문
                           └─ (3단계) 쓰기 작업 — 확인 버튼 필수
                 └─ ④ 결과를 callbackUrl 로 전송 (텍스트/리스트카드/캐러셀 + 바로가기 버튼)
```

### 핵심 제약과 대응
1. **5초 응답 제한** → **AI 챗봇 콜백(useCallback) 승인 필수.** 오픈빌더 관리자센터에서 신청(후기상 2~3일, 사용 이유를 잘 기입). 콜백 URL은 1회용·유효시간이 짧으므로 작업 타임아웃을 그 안으로.
2. **셀러 식별** → 오픈빌더는 채널 단위 사용자 키(botUserKey)만 줌 → 각 플랫폼 계정과 1회 연결:
   - 플랫폼 셀러 화면 → "카카오 챗봇 연결" → 6자리 코드(5분 유효) 발급
   - 챗봇에 `연결 123456` 입력 → botUserKey ↔ 플랫폼 계정 매핑 저장 (셀러브릭스·스튜디오 각각)
   - 해제/재연결 제공
3. **답변 길이 제한** → 요약 + "전체 보기" 버튼(해당 관리자 화면 딥링크).
4. **챗봇은 먼저 말을 걸 수 없음** → 정기 요약은 알림톡(기존 발송 구조) 또는 나에게 보내기.

## 3. 기능 범위
### 1단계 MVP (읽기 전용, 셀러브릭스)
| 셀러 발화 예 | 도구 | 응답 |
|---|---|---|
| "오늘 주문 정리해줘" | `get_orders(period, status)` + 요약 | 건수·금액·결제수단(계좌/카드)·상태별 집계 + 상위 상품 + 미입금/미발송 |
| "입금 안 된 주문 알려줘" | `get_orders(status=UNPAID)` | 리스트카드 + 주문서 바로가기 |
| "이번 주 매출/정산 얼마야" | `get_sales_summary` / `get_settlement` | 요약 텍스트 |
| "송장 아직 안 넣은 주문" | `get_orders(shipping=NONE)` | 리스트 (송장 기능 반영 후) |
| "도움말" | – | 자주 쓰는 질문 퀵리플라이 |

### 2단계 (스튜디오 — 실서버 배포 후)
| 발화 예 | 도구 |
|---|---|
| "이번 주 방송 가능한 스튜디오 추천해줘" | `search_facilities(type, date_range)` |
| "화장품 수요일에 가능한 곳" | `search_facilities(specialty=코스메틱, weekday=수)` + 정렬 |
| "내 다음 예약 언제야" | `get_my_bookings` |
| "스튜디오 주문 정리해줘" | `get_studio_orders` (셀러브릭스 주문과 분리 표시) |

추천 정렬(초안): 날짜·시간 가능(필수: 요일 슬롯 − 불가일 − 시간 차단 − 기존 예약) → 품목 적합도(specialty·장비) → 평점 → 셀러 이용 이력 → 지역.

### 3단계 (쓰기 — 신중히)
예약 생성·예약 문의, 송장 입력, 주문 상태 변경 등. **반드시 "이 작업을 실행할까요? [예/아니오]" 확인 후 실행.** 카드 취소는 기존 규칙(셀러 요청 → 관리자 승인 → 시드페이 취소) 유지.

## 4. 데이터 (신규만, 기존 테이블 변경 없음)
- sellerbricks-bot 쪽 저장: 계정 연결(botUserKey ↔ 플랫폼·계정 ID), 연결 코드, 대화/도구 호출 로그(개인정보 마스킹)
- 각 플랫폼 쪽: 연결 코드 발급/검증에 필요한 최소 테이블(착수 시 설계 보고)

## 5. 서버 구성
- 별도 서비스(같은 EC2 가능, pm2 별도 프로세스), 도메인 예: `bot.sellerbricks.co.kr` (HTTPS 필수)
- 큐: 초기엔 프로세스 내 큐(동시 처리 제한), 사용량 늘면 Redis
- 도구 계층은 MCP 호환 형태

## 6. 보안·법무
- 셀러 범위는 **LLM이 아니라 코드에서 강제**(플랫폼 API가 연결된 계정 범위만 반환)
- 구매자 전화·주소는 부분 마스킹, 상세는 관리자 화면 링크
- 해외 LLM 사용 시 개인정보처리방침에 **처리위탁·국외이전 고지** 추가 필요. LLM에는 집계 위주, 이름·연락처 최소화
- 셀러당 요청 속도 제한, 모든 도구 호출 로그

## 7. 비용(대략)
- 카카오 챗봇 응답 비용은 가입 시 재확인(알림톡은 건당 과금)
- LLM: 질문당 수 원~수십 원, 월 상한 설정
- 서버: 기존 EC2 재사용 시 추가 비용 거의 없음
