# 셀러브릭스 + 셀러브릭스 스튜디오 동시 연결 검토 (2026-11-13)

## 결론
둘 다 연결 가능. **sellerbricks-bot(신규 서버) 1개**가 두 플랫폼을 각각 조회해 답변. 두 플랫폼에는 "연결용 작은 문(내부 봇 API + 챗봇 연결 화면)"만 추가. DB 병합 없음.

## 사용자 답변 (2026-11-13)
1. 스튜디오는 아직 실서버 배포 전 — 다음 주 배포 완료 예정
2. 쇼룸 유형은 지금 추가하지 않음 — 추후 추가
3. 둘 다 쓰는 셀러 / 스튜디오만 / 셀러브릭스만 쓰는 셀러가 모두 있음
4. 두 주문은 각각 독립된 주문

## 개발 위치
| 어디에 | 무엇을 | 규모 |
|---|---|---|
| **sellerbricks-bot** (이 폴더) | 카카오 스킬·콜백, AI 대화, MCP 형식 도구, 계정 연결·로그 저장 | 대부분 |
| 셀러브릭스 (`feature/kakao-chatbot` 브랜치) | ① 셀러 관리자 "카카오 챗봇 연결" 코드 발급 ② 내부 봇 API(주문·매출·정산 읽기) | 작음 |
| 셀러브릭스 스튜디오 (배포 후) | ① 셀러 화면 연결 코드 발급 ② 내부 봇 API(시설 검색·예약 가능 시간·내 예약·스튜디오 주문) | 작음 |

연결 방식 비교:
- A. 챗봇 서버가 두 DB 직접 읽기 — 빠르지만 쓰기 시 스튜디오 예약 정책 우회 위험 → 비권장
- **B. 각 플랫폼 내부 API 호출(서명 키 인증) — 권장.** 업무 규칙은 각 플랫폼 코드가 책임
- C. DB 병합 — 비권장 (MySQL vs PostgreSQL, 둘 다 운영)

## 확인한 코드 사실 (읽기만)
| 항목 | 셀러브릭스 | 셀러브릭스 스튜디오 |
|---|---|---|
| 프레임워크 | Next.js 14 + Prisma 5 | Next.js 14 + Prisma (포트 3007) |
| DB | MySQL (운영 RDS 직결) | PostgreSQL |
| 로그인 | NextAuth v5 credentials, 자체 User | NextAuth credentials, 별도 User (Role: SUPER_ADMIN, MANAGER, FACILITY_ADMIN, BRAND_ADMIN, SELLER, BUYER) |
| 저장소 | `E:\프로젝트\sellerbricks\app` | GitHub `nan29077/sellerbricksstudio` |

스튜디오 보유 데이터(prisma/schema.prisma):
- `Facility`: type(WAREHOUSE 창고 / STUDIO 스튜디오), status(PENDING/APPROVED/SUSPENDED), region, address, specialty(의류·코스메틱·식품 등 콤마 구분), equipment, liveSpaceInfo, openTime/closeTime, capacity, rating, 예약 정책(bookingUnitMinutes, bufferMinutes, minLeadHours, maxAdvanceDays, minHours/maxHours, autoApprove, cancelDeadlineHours). 이용료는 무료(basePrice 미사용)
- `FacilityAvailableSlot`(weekday 0=일~6=토, startTime, endTime), `FacilityBlackoutDate`, `FacilityTimeBlock`, `Booking`(PENDING/APPROVED/REJECTED/CANCELLED/COMPLETED/NO_SHOW), `BookingWaitlist`, `FacilityInquiry`, `FacilityReview`, `FacilityFavorite`, 자체 `Order`/`Settlement`
- `StreamChannel.externalId` 주석: "셀러브릭스와 연동 시 type=ETC + externalId"
- 쇼룸 유형 없음

## 계정 연결
- 챗봇 사용자 1명에 셀러브릭스 계정·스튜디오 계정을 각각 선택적으로 연결
- 연결된 쪽 기능만 노출
- 주문 답변은 [셀러브릭스 주문] / [스튜디오 주문] 분리, 합산 안 함
